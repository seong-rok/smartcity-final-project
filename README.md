# 판교테크노밸리 vs 청라국제업무지구 GIS 비교분석 플랫폼

본 프로젝트는 가천대학교 스마트시티 이론과 실제 기말과제를 위한 웹 기반 GIS 비교분석 플랫폼이다. 본 시스템의 목적은 단순한 지도 시각화가 아니라, **"왜 판교테크노밸리는 성공적인 업무지구가 되었고, 왜 청라국제업무지구는 계획 대비 활성화 수준이 낮은가?"** 를 공공데이터 기반으로 분석하고 설명하는 것이다.

최종 결과물은 GitHub Pages에서 동작하는 웹 GIS 분석 플랫폼이며, 사용자는 판교와 청라의 공간 구조, 접근성, 인구 및 종사자 구조를 한 화면에서 비교할 수 있다.

---

## 1. 프로젝트 개요

### 연구 질문

본 시스템은 다음 여섯 가지 질문에 답해야 한다.

1. 판교와 청라의 토지이용 구조는 어떻게 다른가?
2. 판교와 청라의 교통 접근성은 어떻게 다른가?
3. 판교와 청라의 도달가능 인구 규모는 어떻게 다른가?
4. 판교와 청라의 도달가능 종사자 규모는 어떻게 다른가?
5. 업무시설 집적 수준은 어떻게 다른가?
6. 이러한 차이가 업무지구 성공 여부에 어떤 영향을 미쳤는가?

### 비교 대상

| 구분 | 판교테크노밸리 | 청라국제업무지구 |
|------|---------------|----------------|
| **분석 대상** | 제1판교테크노밸리 | 청라국제업무지구 |
| **기준역** | 판교역 | 청라국제도시역 |
| **위치** | 경기도 성남시 분당구 | 인천광역시 서구 |

### SGIS 자료 상세

SGIS 통계지리정보서비스에서 제공하는 2024-2025년 기준 집계구 단위 데이터를 사용하였다.

- **2024년 총인구**: 집계구별常住 인구로, 접근권역 내 도달가능 인구 산출에 활용
- **2024년 가구총괄**: 집계구별 가구 수로, 주거 밀도 및 정주 특성 분석에 활용
- **2023년 산업분류별 사업체수**: 업무지구 내 사업체 집적도 및 업종 구성 분석에 활용
- **2023년 산업분류별 종사자수**: 업무지구 내 고용 밀도 및 직주비(Jobs-Housing Ratio) 산출에 활용
- **2025년 집계구 경계**: 모든 통계 데이터의 공간적 집계 및 접근권역 내 인구/종사자 집계를 위한 기본 단위 경계로 활용

### 건축HUB 자료 상세

건축행정시스템(건축HUB)에서 수집한 건축물대장 데이터를 사용하였다.

- 판교테크노밸리: 건축물대장 3개 파일 (총괄표제부)
- 청라국제업무지구: 건축물대장 1개 파일 (총괄표제부)

각 건축물의 용도, 연면적, 층수, 주차장 면적 등을 추출하여 KPI 및 공간분석에 활용하였다.

### VWorld 자료 상세

- **베이스맵**: Leaflet 지도의 배경 타일로 VWorld WMTS를 사용하여 대한민국 전역의 고해상도 위성/지도 타일을 제공
- **용도지역 데이터**: 토지이용계획 및 용도지역 정보를 GeoJSON 형태로 제공받아 토지이용 구성비 및 혼합도 분석에 활용

## 3. 분석 방법론

### 3.1 GIS 공간분석

본 프로젝트의 모든 공간분석은 **거리 기반 단순 버퍼가 아닌 실제 네트워크 기반 접근성 분석**을 원칙으로 한다. 즉, 원형 Buffer, 반경 기반 Polygon, 단순 거리 계산은 사용하지 않으며, 반드시 지하철 네트워크의 Graph 분석 결과를 사용한다.

주요 시각화 방식:
- **등시간권 경계(Accessibility Polygon)**: Dijkstra 결과 기반 Convex Hull로 생성
- **집계구 Choropleth**: SGIS 통계 데이터를 집계구 경계에 매핑하여 색상 표현
- **건축물 Polygon**: 건축물대장 좌표를 WGS84로 변환하여 지도 위에 표시

### 3.2 Dijkstra 접근성 분석

수도권 지하철 네트워크를 이용한 접근권역 분석이 본 프로젝트의 핵심 분석 방법이다.

**데이터**: `subway_network/network/nodes.tsv` (915개 역)와 `links.tsv` (1,193개 링크)를 사용한다. `links.tsv`의 `timeFT` / `timeTF` 필드는 역 간 이동시간(초)을 나타낸다.

**분석 과정**:
1. 지하철 역을 노드(Node)로, 역 간 구간을 엣지(Edge)로 하는 **가중 유향 그래프(Weighted Directed Graph)** 를 구축한다.
2. **Dijkstra 최단경로 알고리즘**을 사용하여 판교역(판교)과 청라국제도시역(청라)에서 모든 역까지의 최단 통행시간을 계산한다.
3. 통행시간이 각각 900초(15분), 1800초(30분), 3600초(60분) 이내인 역을 추출한다.
4. 추출된 역들의 좌표를 이용하여 **Graham Scan Convex Hull 알고리즘**으로 접근권역 폴리곤을 생성한다.

**특이사항**: 판교역은 신분당선(판교역)과 경강선(판교역)에 각각 하나씩 총 2개 노드가 존재하므로 다중 시작점(Multi-source) Dijkstra를 수행한다.

**금지 사항**:
- 원형 Buffer 사용 금지
- 반경 기반 Polygon 사용 금지
- 단순 거리 계산 사용 금지

### 3.3 도달가능 인구·종사자 계산

Dijkstra로 산출된 접근권역 내에 포함되는 SGIS 집계구의 인구와 종사자를 집계하여 도달가능 인구 및 종사자를 산출한다.

| 접근권역 | 판교 도달인구 | 청라 도달인구 | 판교 도달종사자 | 청라 도달종사자 |
|---------|-------------|-------------|---------------|---------------|
| **15분** | 473,188명 | 125,316명 | 219,910명 | 42,906명 |
| **30분** | 1,245,231명 | 432,123명 | 628,314명 | 214,532명 |
| **60분** | 2,831,552명 | 1,152,884명 | 1,248,912명 | 518,743명 |

### 3.4 KPI 산출 방식

| KPI | 산출 방식 | 데이터 출처 |
|-----|----------|-----------|
| **총인구** | 업무지구 내 SGIS 집계구 인구 합계 | SGIS 총인구 |
| **총종사자** | 업무지구 내 SGIS 집계구 종사자 합계 | SGIS 종사자수 + 건축물대장 |
| **총사업체수** | 업무지구 내 총 건축물 수 | 건축물대장 |
| **평균 용적률** | (건축물별 연면적 합계 / 대지면적 합계) × 100 | 건축물대장 |
| **총연면적** | 업무지구 내 모든 건축물 연면적 합계 | 건축물대장 |
| **직주비** | 총종사자 / 총인구 | SGIS + 건축물대장 |
| **업무시설 비율** | 업무용 건축물 연면적 / 전체 연면적 × 100 | 건축물대장 |
| **오피스 밀도** | 업무용 건물 수 / 업무지구 면적(㎢) | 건축물대장 |

## 5. 데이터 전처리 및 시스템 구조

### 5.1 데이터 전처리 과정

원본 데이터를 브라우저에서 직접 로드할 수 없는 CSV, TSV, SHP 형식 그대로 사용하지 않고, GitHub Pages 정적 배포에 적합한 GeoJSON 및 JSON 형태로 전처리하였다.

```
┌─────────────────┐     ┌─────────────────┐     ┌──────────────────┐
│  원본 데이터      │     │  전처리 과정      │     │  웹서비스         │
│                  │     │                  │     │                  │
│  CSV (건축물대장)  │────▶│  GeoJSON 변환    │────▶│  deploy_data/    │
│  TSV (지하철망)    │────▶│  JSON 변환       │────▶│  *.geojson       │
│  SHP (SGIS 통계)  │────▶│  좌표계 변환      │────▶│  *.json          │
│  Zipped Shapefile │────▶│  속성 정제        │────▶│  (정적 파일)      │
└─────────────────┘     └─────────────────┘     └──────────────────┘
```

| 원본 파일 | 전처리 결과 | 전처리 내용 |
|-----------|------------|-------------|
| `건축물대장.csv` | `pangyo_buildings.geojson`, `cheongna_buildings.geojson` | 좌표 변환(WGS84), 건물 용도 분류, 연면적/층수/종사자수 속성 추출 |
| `nodes.tsv`, `links.tsv` | `subway_nodes.json`, `pangyo_routing.json`, `cheongna_routing.json` | TSV → JSON 변환, 그래프 구축, Dijkstra 최단경로 사전 계산 |
| `SGIS 통계 SHP` | `pangyo_population.geojson`, `cheongna_population.geojson` | 집계구 통계를 접근권역 단위로 집계, 인구/종사자 속성 부여 |
| `시군구 경계 SHP` | `pangyo_boundary.geojson`, `cheongna_boundary.geojson` | 업무지구 경계 추출 및 단순화 |

**전처리 원칙**:
1. **원본 데이터 불변**: 모든 원본 CSV/TSV/SHP 파일은 수정하지 않고 보존
2. **사전 계산(Pre-computation)**: Dijkstra 알고리즘은 빌드 시점에 한 번만 실행하여 결과를 JSON으로 저장
3. **지역 분할 저장**: 판교와 청라 데이터를 별도 GeoJSON 파일로 분할하여 병렬 로딩 최적화
4. **정적 파일 배포**: 서버 측 처리 없이 브라우저가 GeoJSON/JSON만 읽도록 설계

## 6. UI 및 시각화 설계

모든 탭에서 동일한 지도 표현을 반복하지 않으며, 각 탭은 서로 다른 질문에 답한다. 지도만 보아도 현재 어떤 분석을 수행하는지 알 수 있어야 한다.

| 탭 | 시각화 중심 | 답하는 질문 |
|----|-----------|-----------|
| 핵심 비교 | 업무지구 경계 + KPI 카드 | 판교와 청라의 핵심 차이는 무엇인가? |
| 공간 비교 | 접근권역 Polygon + 역 마커 | 접근권역은 어떻게 다른가? |
| 토지이용 | 건축물 용도별 색상 Polygon | 토지는 어떻게 이용되고 있는가? |
| 교통 접근성 | 지하철 노선 + 등시간권 | 광역 교통망 연결성은 어떻게 다른가? |
| 인구·산업 | 집계구 Choropleth | 인구와 산업은 어떻게 분포하는가? |

### 6.1 핵심 비교

**지도 표현**:
- 업무지구 경계 표시 (판교: 파랑, 청라: 보라)
- 기준역(판교역/청라국제도시역) 강조 마커
- 15분 접근권역(반투명 채움), 30분 접근권역(점선)
- 주요 업무시설 점 마커

**KPI 카드**:
- 총인구, 총종사자, 총사업체수
- 총연면적, 평균 용적률, 직주비
- 판교/청라 값과 비율 함께 표시

**하단 패널**: 성공요인 비교표

### 6.2 공간 비교

**지도 표현**:
- 15분(보라), 30분(파랑), 60분(초록) 접근권역 Polygon
- 도달 시간대별 역 마커 색상 구분
- 시작역 강조 마커

**차트**: 15/30/60분 접근인구 및 접근종사자 막대그래프

**하단 패널**: 접근권역별 도달인구/종사자 수치 및 내러티브 분석

### 6.3 토지이용

**지도 표현**:
- 건축물 Polygon을 용도별 색상으로 표시
  - 업무시설(파랑), 상업시설(주황), 주거시설(초록)
  - 교육·연구시설(보라), 공공시설(회색)
- 30분 접근권역 점선 중첩

**팝업 정보**: 건축물명, 주용도, 연면적, 대지면적, 용적률

**차트**: 건축물 용도 비율 도넛 차트 (판교/청라 각각)

**하단 패널**: 용적률 및 토지이용 특성 비교 내러티브

### 6.4 교통 접근성

**지도 표현**:
- 지하철 노선 굵은 선으로 표시 (색상: 신분당선 빨강, 경강선/공항철도 파랑, 7호선 보라)
- 주요 역 원형 마커
- 15분/30분 접근권역 중첩
- 주요 고용 중심지(강남, 여의도, 서울역, 인천공항 등) 마커
- 광역 교통축 라벨 (예: "신분당선 → 강남 13분")

**차트**:
- 주요 고용중심지 도달시간 비교 (가로 막대)
- 교통 접근성 레이더 차트 (강남/공항/도심/광역/철도)

**하단 패널**: 광역 교통망 기반 노동시장 접근성 내러티브

### 6.5 인구·산업

**지도 표현**:
- 집계구 Choropleth Map
- 선택 가능 지표: 총인구, 총종사자수, 총사업체수, 종사자 밀도, 직주비

**색상 규칙**:
- 총인구: 연한 파랑 → 진한 파랑
- 총종사자수: 연한 빨강 → 진한 빨강
- 총사업체수: 연한 보라 → 진한 보라
- 직주비: 연한 회색 → 진한 남색

**팝업 정보**: 집계구 ID, 행정동명, 총인구, 총종사자수, 총사업체수, 종사자 밀도, 직주비

**차트**: 동별 인구/종사자, 산업별 종사자 비율

**하단 패널**: 자족 기능 및 직주 균형 진단 내러티브

### 지도 레이어

사용자가 켜고 끌 수 있는 레이어: 업무지구 경계, 지하철역, 지하철 노선, 30분 등시간권, 60분 등시간권, 인구 정보, 종사자 정보, 건축물 용도

### 지도 팝업

건축물 또는 집계구 클릭 시 표시 정보: 건축물 주용도, 연면적, 용적률, 인구, 종사자수

## 10. 연구적 의의 및 최종 목표

본 프로젝트는 단순한 지도 시각화 서비스가 아닌, **GIS 기반 도시공간분석 플랫폼**으로서 다음과 같은 연구적 의의를 가진다.

### 업무지구 성공요인 분석

판교테크노밸리와 청라국제업무지구는 모두 대한민국을 대표하는 경제자유구역이지만, 개발 성과에서 큰 차이를 보인다. 본 프로젝트는 두 업무지구의 **공간적 요인**에 초점을 맞추어 성공요인을 정량적으로 분석한다.

| 분석 항목 | 판교테크노밸리 | 청라국제업무지구 | 분석 방법 |
|-----------|---------------|----------------|-----------|
| **총인구** | 85,231명 | 48,765명 | SGIS 집계구 데이터 |
| **총종사자** | 99,842명 | 28,314명 | 건축물대장 + SGIS |
| **평균 용적률** | 486% | 218% | 건축물대장 (연면적/대지면적) |
| **직주비** | 1.17 | 0.58 | 종사자/인구 비율 |
| **업무시설 비율** | 45% | 25% | 건축물 용도 분류 |
| **오피스 밀도** | 127동/㎢ | 16동/㎢ | 업무용 건물수/면적 |

### 노동시장 접근성 분석

Dijkstra 알고리즘 기반 접근권역 분석을 통해 두 업무지구의 광역 노동시장 접근성 차이를 계량화한다. 판교는 30분 내 124만 명, 60분 내 283만 명의 노동인구에 도달하여 청라(30분 43만 명, 60분 115만 명) 대비 약 2.5~3배 넓은 광역 노동시장에 접근이 가능하다.

### 핵심 연구 질문: "왜 판교는 성공하고 청라는 어려움을 겪는가?"

본 분석은 다음과 같은 공간적 요인이 핵심임을 제시한다.

1. **강남 초연결성**: 판교는 신분당선을 통해 강남까지 13분에 도달하여 약 250만 명의 고급 노동력에 접근
2. **고밀 업무 집적**: 판교의 평균 용적률 486%는 청라(218%)의 2.23배로, 단위 면적당 경제 활동 밀도가 압도적으로 높음
3. **직주비 격차**: 판교(1.17)는 자족형 업무중심지이나 청라(0.58)는 주거배후형 혼합지구로 기능
4. **해양 장벽 vs 광역 연결**: 청라는 서쪽 해양 장벽으로 인해 도달가능 면적이 제한되는 반면, 판교는 경강선/신분당선으로 경기 동부-강남 축에 편입

### 최종 목표

최종 시스템은 다음 사실을 데이터로 보여줄 수 있어야 한다.

판교는 **높은 업무시설 집적, 높은 종사자 밀도, 넓은 접근권역, 큰 노동시장 접근성**을 가진다. 청라는 **상대적으로 작은 접근권역, 낮은 종사자 밀도, 낮은 업무시설 집적도**를 가진다. 이 차이가 업무지구 성공 여부에 영향을 미쳤음을 지도와 통계로 설명하는 것이 본 프로젝트의 최종 목표이다.

### 활용 가치
